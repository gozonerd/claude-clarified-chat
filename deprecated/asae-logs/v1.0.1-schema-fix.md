## Defect

CCC v1.0 shipped with 293 tests / 100/100/100/100 coverage / all Step 7 gates green / IP-clean / gate-attested. The build was real. But the test fixtures were **synthesized from CCC's own schema** rather than derived from real Claude Desktop exports. Result: when a real Claude zip was dropped into the running app, every `.jsonl` line failed `EventSchema.safeParse` and rendered as "unavailable" while still being counted. The whole test suite was internally consistent and externally invalid.

This is a candidate **F13 — fixture-tautological validation** — distinct from F7 (audit-on-intent) because the audit DID run, coverage IS real, convergence WAS earned. The defect is that the fixtures + the schema were synthesized from each other, so passing the suite proves nothing about real-world inputs.

## Empirical truth (vs. the fictional v1.0 schema)

Scanned across 3 real Claude Desktop export `.jsonl` files (1699 total events):

| Field | v1.0 fictional schema | Real Claude Desktop |
|---|---|---|
| Top-level identifier | `id: z.string().min(1)` (REQUIRED) | `uuid` (and only on conversational/system/attachment); `id` appears 0/1699 times |
| `type` enum | `user \| assistant \| tool_use \| tool_result \| thinking \| system` (6) | `user \| assistant \| system \| queue-operation \| last-prompt \| custom-title \| attachment` (7 — pre-fix briefing missed `custom-title`, 113 occurrences across the 3 exports) |
| Payload location | flat `content` at top level | `message.content` for assistant/user (string OR array of inner blocks); top-level for queue-operation only; `attachment` for attachment |
| Inner content blocks | (none — flat) | `text`, `tool_use`, `tool_result`, `thinking` inside `message.content[]` |
| Sub-agent routing | `subagent_id` flat field | `isSidechain: boolean` + `parentUuid` chain |
| `metadata.json` field names | snake_case (`session_id`, `created_at`, ...) | camelCase (`sessionId`, `createdAt`, ...) |
| `metadata.json` timestamps | ISO datetime strings | Epoch milliseconds (numbers) |

The pre-fix briefing claimed `id` 0/420 in a single file scan. The 3-file scan above confirms `id` 0/1699 across all sizes and refines the type enum from 6 to 7.

## Architecture

Two distinct schemas now coexist:

1. **`RawEventSchema`** (`src/schemas/event.ts`) — empirically derived discriminated union over 7 raw types, each with `.passthrough()` for forward-compat against future Claude Desktop additions. Used by parser for input validation only.
2. **`DisplayEvent`** type — flat shape with `id`/`type`/`timestamp`/`content`/optional `subagent_id`/optional `tokens`/optional `raw`/optional `source_path`. The `type` enum widens to 10 values (the 7 raw types plus the 3 inner-block types `tool_use`/`tool_result`/`thinking` that appear when assistant messages are flattened). Consumed by store, UI, exporters, secret detector, token waterfall.

A normalization layer in `src/core/parse/normalize.ts` projects RawEvent → DisplayEvent[]:

- Conversational events (`user`/`assistant`) with array `message.content` flatten to one DisplayEvent per inner block. ID = `<uuid>#<blockIdx>`. Tokens attach to the first block of each assistant message so the waterfall sums per-message, not per-block.
- Conversational events with string `message.content` map 1:1.
- Session-meta types (`queue-operation`, `last-prompt`, `custom-title`, `attachment`) and `system` events map 1:1 with synthesized IDs and shape-appropriate content extraction. **Never filtered** — filtering would re-create the F13 "counted-but-hidden" anti-pattern.
- `isSidechain: true` events route the `parentUuid` into `subagent_id` so the existing token-waterfall sub-agent attribution keeps working without any sub-agent metadata files.

The `Event = DisplayEvent` type alias kept downstream `import type { Event }` consumers (~9 files) working with no source changes beyond updating the consumer's mental model. Existing factory-style tests (`createEvent({ id: 'e1', type: 'user', content: 'hello' })`) keep passing because their output happens to match the DisplayEvent shape.

## Disclosures

- **Pass-1 verification chain bug (self-corrected):** the initial Pass 1 invocation used `npm run lint 2>&1 | tail -5; echo "exit=$?"` which captures `tail`'s exit code, not lint's. This is exactly the F10 sub-agent failure mode (proxy metric instead of literal shell exit) — caught here in the parent thread because the lint output itself contained an obvious error message. Pass-1-restart and Passes 2/3 used `npm run X >log 2>&1; rc=$?` to capture the literal exit code. Documenting the bug surfaced rather than silently fixed.
- **Forward-compat passthrough trade-off:** `RawEventSchema` uses `.passthrough()` on all conversational types. This accepts unknown future Claude Desktop fields rather than rejecting them. Trade-off: a malformed event with mistyped optional fields (e.g., `userType: 42` instead of `userType: "external"`) would still parse if the discriminator + required fields are correct. Acceptable for forward-compat; alternative was to ship strict and watch every Claude Desktop minor version break the parser.
- **Subagent metadata files:** real Claude Desktop exports don't have a `subagents/` directory. The existing CCC parser code that handles `subagents/*.meta.json` and `subagents/*.jsonl` is now dead-on-real-exports but kept because the synthetic test fixtures still exercise it (and removing it would gratuitously break the existing 9 `subagents/` test paths). `isSidechain: true` events route through `subagent_id` instead, which is the empirical sub-agent signal.
- **Coverage discipline (no apparatus manipulation, per F11):** branch-coverage gaps were filled by adding real test cases (`output_tokens`-only, `null` usage, queue-op without timestamp, attachment with all defaults, `loadRealExportJsonlLines` throw-path with a temp empty fixture dir). No `/* c8 ignore */` pragmas were added; no thresholds were lowered.

## IP-clean discipline at filesystem level

The real Claude Desktop export `.zip` files used as canonical anchors for F13 prevention are **gitignored** (`app/.gitignore` excludes `src/__fixtures__/real-exports/*.zip` and `src/__fixtures__/real-exports/*-extracted/`). Real exports contain session content and working-directory paths that constitute identifying information; per the public-portfolio-codebase IP-clean discipline they cannot be committed. The F13 acceptance test suite uses `describe.runIf(realExportFixturesPresent())` so:

- **Local dev with fixtures present:** F13 acceptance tests run, full integration coverage of real-shape input
- **Public CI without fixtures:** F13 acceptance tests skip cleanly; coverage stays 100% via inline empirical-shape unit tests in `normalize.test.ts` and the schema test rejection cases that don't depend on fixtures

`app/src/__fixtures__/real-exports/README.md` documents the contributor flow for populating fixtures locally.
