## 2. Testing Taxonomy Applicability

### 2.1 Test Categories (Part 1 — 20 Categories)

**Unit Tests**
- Applies: **YES**
- Exit criteria: 100% line + 100% branch coverage on all testable modules; every FR-NN has at least one unit test asserting its acceptance criteria; median test runtime ≤ 50ms; no flakes across 20 consecutive runs.

**Integration Tests**
- Applies: **YES**
- Exit criteria: Parser Engine + Event Store integration verified against a reference test corpus; Export Engine + Secret Pattern Detector integration verified (pre-export warning fires when secrets present); Ingest Adapter + Parser Engine integration verified on malformed zips; **Source-zip immutability verified: SHA-256 hash of source zip unchanged before vs. after full ingest + export cycle (operationalizes TRD 3.2 RPO = 0)**; runtime budget ≤ 10s per test suite.

**Component / Module Tests**
- Applies: **YES**
- Exit criteria: Every AVD Section 3.1 component has its own test module; Timeline Renderer, Detail View Renderer, Export Engine, Accessibility Layer each tested in isolation with stub store; component-internal state transitions covered.

**End-to-End (E2E) Tests**
- Applies: **YES**
- Exit criteria: Every PRD user journey (J1, J2, J3) has at least one E2E test; every edge-case journey (E1, E2, E3) has at least one E2E test; E2E suite runs on every PR via Playwright; zero flakes across 20 consecutive runs. **Browser matrix (operationalizes TRD 3.7 target platforms):** if web form-factor, each PR-gating E2E run executes against Chromium (≥ 120), Firefox (≥ 120), and WebKit (Safari ≥ 17) via Playwright's multi-browser project config; if desktop form-factor, E2E runs against the desktop-runtime webview on Windows 11, macOS 13+, and Ubuntu 22.04+ in CI.

**Functional Tests**
- Applies: **YES**
- Exit criteria: Every TRD FR-001 through FR-017 has a functional test asserting its acceptance criterion verbatim; mapping table maintained in test README.

**Regression Tests**
- Applies: **YES**
- Exit criteria: CI runs full suite (unit + integration + component + E2E + accessibility + performance) on every PR; merge blocked if any suite fails; historical bug catalog — every fixed bug gets a regression test preventing recurrence.

**Smoke Tests**
- Applies: **YES**
- Exit criteria: Post-build smoke: ingest of reference 300-line zip + timeline render + single export to MD completes in ≤ 30s; smoke failures block release.

**Sanity Tests**
- Applies: **YES**
- Exit criteria: Minimal sanity suite (≤ 5 tests) for hotfix verification; covers ingest, timeline render, one export format; runs in ≤ 60s.

**Acceptance Tests (UAT)**
- Applies: **YES**
- Exit criteria: Primary user (Krystal) runs MVP against ≥ 5 existing Claude threads within 7 days of ship and logs ≥ 1 non-trivial finding per thread, per PRD G5. Findings catalogued in `docs/acceptance/` with timestamp + thread id + finding type.

**Contract Tests (API-level)**
- Applies: **NO**
- Skip reason: Product has no API surface (per PRD Section 3.3 and TRD 4.1/4.2). No external or internal API contracts to test.

**Performance Tests**
- Applies: **YES**
- Exit criteria: Every TRD 3.1 metric enforced in automated test: time-to-first-insight p50 ≤ 5s / p95 ≤ 10s / p99 ≤ 15s for 300-line JSONL; Clarity Corpus export p50 ≤ 30s / p95 ≤ 60s / p99 ≤ 90s; streaming ≥ 100 events per 200ms chunk; search p95 ≤ 300ms for 10k events; memory ≤ 500MB for 10k-event export. Test corpus includes 100-line, 300-line, 1k-line, 10k-line, 50k-line reference zips. Performance regressions block merge.

**Security Tests**
- Applies: **YES**
- Exit criteria: Applicable standards from TRD 3.3 (OWASP ASVS Level 1, CERT secure coding) operationalized in Section 3 below. Specific tests: zip-slip prevention (malicious zip with `../` paths rejected); zip-bomb guard (per-file decompression cap enforced); no-dynamic-code-execution on user content (static analysis); no-runtime-network (CI test: app runs with network disabled; static analysis: no network-call APIs imported).

**Usability Tests**
- Applies: **YES**
- Exit criteria: At least 3 non-dev users outside primary-user's circle complete J1 + J3 unaided within a 15-minute session (measured in week-2 dogfood post-MVP); cognitive-accessibility navigation guarantee (≤ 2 steps between any two views) verified by route-graph validator at build time.

**Accessibility Tests**
- Applies: **YES — always for UI, hardwired**
- Exit criteria: WCAG 2.1 AA minimum. axe-core via Playwright runs on every UI state; **zero** `critical` or `serious` violations. Manual protocol: NVDA + Chrome, JAWS + Chrome, VoiceOver + Safari — every PR touching UI gets a screen-reader pass before merge; every release gets keyboard-only walkthrough of J1/J2/J3; cognitive-accessibility review per release. PDF/UA validation for every PDF export artifact.

**Snapshot / Visual Regression Tests**
- Applies: **YES**
- Exit criteria: Visual snapshots captured for every primary view in default + dark + reduced-motion + large-text themes; unapproved pixel diffs block merge; snapshot updates require human review.

**Property-Based / Fuzz Tests**
- Applies: **YES**
- Exit criteria: Parser Engine fuzzed against randomly-generated JSONL with 10,000 iterations per CI run; property invariants: (a) every parsed event has a deterministic id; (b) parse is idempotent; (c) malformed input produces `[unavailable]` marker, never unhandled exception; (d) zip-slip attempts rejected 100% of the time; (e) zip-bomb decompression bounded 100% of the time.

**Mutation Testing**
- Applies: **YES**
- Exit criteria: Mutation score ≥ 80% on Parser Engine + Event Store + Export Engine + Secret Pattern Detector (these are the correctness-critical modules). Mutation testing runs weekly in CI (not per-PR to keep feedback loop fast).

**CI/CD Pipeline Tests**
- Applies: **YES — always if the project uses git**
- Exit criteria: GitHub Actions workflow runs on every PR: unit + integration + component + E2E + accessibility + performance + security + fuzz. Required statuses: all test jobs green. Merge protection: main branch requires passing statuses + passing pre-commit hooks (axe-core + coverage + secret scan + static type check).

**Canary / A/B Testing (in production)**
- Applies: **NO**
- Skip reason: Single-user local app with no centrally-observed production surface. No canary or A/B infrastructure.

**Monitoring / Observability (post-deploy)**
- Applies: **NO**
- Skip reason: Per TRD 3.8, product has no post-deploy production-operation surface — no remote telemetry, no metrics aggregation, no dashboards. Local audit log (TRD SR-004) is user-controlled introspection, not operational observability.

## 8. Security Quality Gates

From TRD Section 3.3, operationalized as pre-commit and CI gates.

### 8.1 Pre-Commit Gates

- **Secret scanning:** scan staged files for secret patterns (API keys, JWT, private keys); block commit if detected. Tool: gitleaks or equivalent.
- **Dependency vulnerability scan:** scan against CVE database; block commit on new high-severity (CVSS ≥ 7.0) vulnerabilities in the dependency graph. Tool: npm audit / cargo audit / pip-audit per language.
- **Static analysis:** block commit on high-severity static analysis findings in modified code. Tool: language-specific linter + security linter.
- **Type check:** block commit on type errors in modified code.
- **axe-core on modified UI:** block commit on new `critical` or `serious` accessibility violations.
- **Coverage delta:** if coverage drops below 100% line or 100% branch for any modified module, block commit.
- **Documentation floor (operationalizes TRD 3.6):** docstring-presence linter enforces module-level docstring on every module and public-function docstring on every public function; README must cover install + first-use + export sections; block commit on any docstring absence in modified code.

### 8.2 CI Gates

- **Full dependency audit:** on every PR; block merge on any unresolved high-severity CVE.
- **SBOM generation:** produced per release; archived with release artifact.
- **License compliance check:** block on incompatible licenses in dependency graph (e.g., GPL in an MIT-intended product).
- **Network-call static analysis:** assert no network-call APIs imported (enforces TRD SR-003 strict no-network).
- **Full security test suite:** zip-slip + zip-bomb + secret-detection + no-dynamic-exec tests.

### 8.3 Pre-Deploy Gates

- **Penetration-style review** of the release artifact: verify no network calls on test run with network disabled; verify local audit log contains only expected event types with no unexpected fields.
- **Security review sign-off** by Author before tagging release.
- **Production configuration audit:** none (no production environment), but release-tag metadata reviewed.
